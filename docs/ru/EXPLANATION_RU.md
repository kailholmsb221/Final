# Campus Courier AI — подробный разбор (на русском)

Файл для команды: что делает каждая часть проекта и почему. Читать сверху вниз,
параллельно открыв код.

---

## 0. Идея в одном абзаце

Робот везёт документы из почты (S) в деканат (G). Короткий путь идёт через коридор C,
который иногда перекрыт. В коридоре стоит датчик, который иногда ошибается. Нужно решить:
рисковать коротким путём или идти длинным обходом.

* **A\*** (тема «поиск») находит два маршрута: короткий через C (7 шагов) и обход без C
  (11 шагов).
* **Байес** (тема «вероятности») превращает сигнал датчика в вероятность того, что C
  перекрыт.
* **MDP** (тема «последовательные решения») превращает длины маршрутов в награды и с
  учётом этой вероятности выбирает действие: *Proceed* (идти через C) или *Detour* (обход).

Алгоритмы связаны: без A\* у MDP нет наград, без Байеса нет вероятности, а ответ MDP
выбирает, какой маршрут A\* выполнять. Это и есть требование задания: алгоритмы работают
на общую цель, а не отдельно друг от друга.

## 1. `grid.py` — карта

* Карта задаётся строками: `S` старт, `G` цель, `C` коридор с датчиком, `#` стена, `.`
  свободно.
* `Grid.from_strings` разбирает строки и запоминает координаты стен, S, G и C. Клетка
  записывается как `(строка, столбец)`, счёт с нуля.
* `neighbors(cell)` возвращает соседей вверх, вниз, влево и вправо, если они внутри карты
  и не стена. Ходить можно только в 4 стороны, каждый шаг стоит 1.
* `with_blocked(cell)` делает копию карты, где C превращается в препятствие. Так считается
  обход.
* `render(path)` рисует карту в консоли, `*` обозначает маршрут.

## 2. `search.py` — A\* (алгоритм 1)

### Что такое A\*

Поиск, который всегда раскрывает клетку с минимальным
**f(n) = g(n) + h(n)**:

* `g(n)` — сколько шагов уже прошли от старта до n (точно);
* `h(n)` — оценка, сколько осталось до цели. У нас это **манхэттенское расстояние**
  `|r − r_G| + |c − c_G|`.

### Почему путь оптимален

Ходим только по 4 направлениям с ценой 1, значит до цели нельзя дойти быстрее, чем за
манхэттенское расстояние. Оценка `h` **никогда не завышает** настоящую стоимость
(*admissible*, допустимая эвристика). Отсюда следует: когда A\* впервые достаёт цель из
очереди, найденный путь самый короткий.

### Как устроен код

* `frontier` — куча (`heapq`), в ней кортежи `(f, h, счётчик, клетка)`. Куча всегда отдаёт
  минимальный `f`. При равном `f` берётся меньший `h`, то есть клетка ближе к цели.
  Счётчик нужен, чтобы порядок был одинаковым при каждом запуске.
* `g` — словарь лучших известных расстояний от старта.
* `came_from` хранит, откуда пришли в клетку, и по нему восстанавливается путь (`_rebuild`).
* `closed` — уже раскрытые клетки. В куче могут лежать старые, более дорогие копии клетки,
  их пропускаем.
* Для каждого соседа считаем `new_g = g[cell] + 1`. Если это лучше известного, обновляем и
  кладём соседа в кучу с `f = new_g + h`.

### BFS

Поиск в ширину, обычная очередь. Для одинаковой цены шага он тоже находит кратчайший путь,
но не знает, где цель, поэтому раскрывает больше клеток. В проекте BFS нужен только для
сравнения: на нашей карте A\* раскрывает 10 клеток, BFS 18.

### Результат на карте

Короткий путь: (0,0)→(0,1)→(0,2)→(1,2)→(2,2)→**(2,3)=C**→(2,4)→(2,5), всего 7 шагов.
C стоит на 5-м шаге. Обход без C идёт через нижний ряд и занимает 11 шагов.

## 3. `bayes.py` — формула Байеса (алгоритм 2)

### Модель датчика

* B — «коридор перекрыт», ¬B — «свободен».
* Датчик говорит `alarm` (тревога) или `clear` (чисто).
* Чувствительность P(alarm | B) = 0.9: когда перекрыто, датчик срабатывает в 90% случаев.
* Ложная тревога P(alarm | ¬B) = 0.2: когда свободно, он всё равно срабатывает в 20%.
* Априорная вероятность P(B) = 0.2: в 20% случаев коридор перекрыт (наше допущение).

### Формула

```
P(B | e) = P(e | B)·P(B) / [ P(e | B)·P(B) + P(e | ¬B)·P(¬B) ]
```

Знаменатель — полная вероятность увидеть такой сигнал (`evidence` в коде).

### Пример (выучить наизусть)

Одна тревога: числитель 0.9·0.2 = 0.18, ложные тревоги 0.2·0.8 = 0.16,
P(B | alarm) = 0.18 / (0.18 + 0.16) = 0.18 / 0.34 = **0.529**.

Смысл: даже после тревоги коридор перекрыт только с вероятностью около 53%, потому что
ложных тревог почти столько же, сколько настоящих.

«Чисто»: 0.1·0.2 / (0.1·0.2 + 0.8·0.8) = 0.02 / 0.66 = **0.030**.

### Несколько сигналов

`bayes_sequence` применяет формулу по очереди: апостериорная вероятность становится новой
априорной. Это корректно, если сигналы **условно независимы** при известном состоянии
коридора. Две тревоги дают 0.835, тревога и потом «чисто» дают 0.123. Порядок сигналов на
результат не влияет, это проверено тестом.

## 4. `mdp.py` — MDP и value iteration (алгоритм 3)

### Что такое MDP

Набор (S, A, T, R, γ): состояния, действия, вероятности переходов, награды и коэффициент
дисконтирования. У нас:

| Состояние | Действие | Куда попадём | Награда |
|---|---|---|---|
| Free | Proceed | Delivered | 20 − 7 = **13** |
| Free | Detour | Delivered | 20 − 11 = **9** |
| Blocked | Proceed | Free (0.4) или Blocked (0.6) | −(2·5 + 4) = **−14** |
| Blocked | Detour | Delivered | **9** |

* 20 — награда за доставку, минус 1 за каждый шаг. Длины 7 и 11 берутся из A\*.
* Если пошли в перекрытый коридор: 5 шагов туда, 5 обратно, плюс штраф 4 за задержку,
  итого −14. Пока шли назад, коридор с вероятностью 0.4 освободился.
* Delivered — конечное состояние, V = 0. γ = 0.9.

### Уравнение Беллмана и value iteration

```
V(s) = max_a Σ T(s,a,s') · [ R(s,a,s') + γ·V(s') ]
```

Value iteration начинает с V = 0 и повторяет это обновление, пока значения меняются
больше, чем на 10⁻⁶ (`theta`).

* Итерация 1: V(Free) = max(13, 9) = 13; V(Blocked) = max(−14 + 0, 9) = 9.
* Итерация 2: значения те же, сходимость.

Q-значения, то есть ценность конкретного действия в состоянии:

* Q(Free, Proceed) = 13, Q(Free, Detour) = 9
* Q(Blocked, Detour) = 9
* Q(Blocked, Proceed) = −14 + 0.9·(0.4·13 + 0.6·9) = −14 + 0.9·10.6 = −14 + 9.54 = **−4.46**

Политика: если свободно, идти через C, если перекрыто, обходить.

### Как связать с Байесом (QMDP)

Робот **не знает**, свободен коридор или нет. У него есть только вероятность b = P(B) от
Байеса. Поэтому каждое действие оценивается как среднее, взвешенное по этой вероятности:

```
Q_b(a) = b·Q(Blocked, a) + (1 − b)·Q(Free, a)
Proceed: 13 − 17.46·b        Detour: 9
```

Значения равны при b = 4 / 17.46 = **0.229**, это порог. Если вероятность блокировки
выше 22.9%, выгоднее обход.

* b = 0.2 (сигнала нет): Proceed = 9.51 > 9 → **идём через C**.
* b = 0.529 (одна тревога): Proceed = 3.76 < 9 → **обход**.

`decision_threshold` считает этот порог по формуле, `belief_q` считает Q_b.

### Особый случай

Если обхода нет, Detour означает «отменить доставку» с наградой −20. Тогда порог
поднимается почти до 1: робот рискует, пока не уверен в блокировке почти на 100%.

## 5. `pipeline.py` — всё вместе

`run_mission` выполняет шаги по порядку:

1. A\* по карте → короткий путь. BFS для сравнения.
2. Байес по сигналам → b.
3. Если C не на коротком пути, решение не нужно: просто идём (Proceed).
4. A\* по карте без C → обход. `dist` — на каком шаге пути стоит C.
5. Строим MDP из длин, решаем value iteration, считаем Q_b и выбираем максимум.
6. Итоговый маршрут: короткий при Proceed, обход при Detour.

Всё возвращается в одном объекте `MissionReport`, который показывают CLI и UI.

## 6. `cli.py`, `app.py`, `experiments.py`

* `python -m campus_courier` печатает каждый алгоритм в формате вход → шаги → выход →
  объяснение, как требует задание.
* `streamlit run app.py` открывает интерфейс. Слева параметры, справа карта и три вкладки
  с промежуточными расчётами.
* `python -m campus_courier.experiments`:
  * A\* против BFS на случайных картах: длина пути одинаковая всегда, клеток раскрыто на
    51–79% меньше;
  * симуляция 20 000 доставок: наша стратегия даёт 11.26, «верить датчику» 10.94,
    «всегда обход» 9.00, «всегда напрямую» 5.97, «оракул» 12.19.

## 7. Тесты (`tests/`)

235 тестов. Главные:

* значения Байеса совпадают с ручным расчётом (0.529, 0.030, 0.835);
* Q-значения совпадают с ручным расчётом (13, 9, −4.46, 9), уравнение Беллмана выполняется;
* на 200 случайных картах A\* даёт ту же длину, что BFS, и раскрывает не больше клеток;
* решение меняется ровно на пороге 0.229;
* крайние случаи: цель недостижима, обхода нет, неверные вероятности.

Запуск: `python -m pytest -q`.
